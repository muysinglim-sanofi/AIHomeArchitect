# ABA merchant-review UI — preprod only

**Deployed:** https://preprod.aydenstudio.com (Firebase site `ayden-studio-preprod`)
**API:** `ayden-api-staging.fly.dev` · **PayWay:** sandbox · **No real payment was made.**
Production Supabase, production PayWay, the Render backend, RevenueCat, DNS and
`app.aydenstudio.com` were not touched. `frontend/lib` and `frontend/ios` were not opened.

---

## 1. ABA KHQR is the only method, enforced at the source

`PAYWAY_PAYMENT_OPTION = "abapay_khqr"` in `backend/fly.toml`, deployed to the
staging Fly app.

This was previously **empty**, which is documented behaviour meaning "PayWay
draws its own chooser" — and that chooser, decoded from a real sandbox token on
2026-08-19, offers `cards`, `abapay_deeplink`, `abapay_khqr_deeplink` and
`abapay_khqr`. Any recette capture taken before today would have shown a
Credit/Debit Card button and contradicted the approved deck.

Measured after the change, on a live sandbox transaction: the checkout token now
begins `{"qr_string":"03…` and ABA's page renders KHQR only — red KHQR header,
`Scan. Pay. Done.`, three steps, one real QR, ABA's own footer. No card anywhere.

Rollback is deleting that one line.

## 2. The checkout is a modal over the same Wallet

`_ContinueToAbaButton` used to hand the browser to `location.href`. That unloads
the Flutter app, so the Wallet, the payment attempt and the poll waiting on it
were destroyed, and a returning payer arrived at a cold boot.

It now embeds ABA's own `checkout_url` in an `<iframe>`, in a sheet over a Wallet
that stays mounted and stays polling. The barrier dropped from 0.72 to 0.45 and
the sheet from 0.94 to 0.90 of the viewport, so the Wallet reads through.

Nothing is redrawn. No QR, no amount, no bank mark is generated by Ayden — the
frame renders the URL the SERVER received from PayWay. Check Transaction remains
the only authority on whether money moved; the frame is cross-origin and reports
nothing, deliberately.

`Open ABA PayWay in a new tab` sits under the frame and is never hidden: if ABA's
page fails to render, this widget cannot detect it, so the escape must always be
there. It opens a NEW tab (`window.open` + `noopener`), never this one.

### The frame is sandboxed — and the claim that it could not be, was wrong

This section previously said the `sandbox` attribute prevented ABA's page from
rendering. **That was a false diagnosis** and it has been corrected: the blank
frame was a page caught mid-load, and the "fix" was six extra seconds rather
than the missing attribute.

Re-measured with each condition given 18-22 s, the original four-token sandbox
renders ABA's page completely. The attribute is restored. The one token that
does break it is `allow-same-origin`, whose removal produces a visually
identical failure from a different cause.

Full evidence, per capability, with the live headers and the deployed bundle:
[ABA_IFRAME_SECURITY_NOTE_2026_09_04.md](./ABA_IFRAME_SECURITY_NOTE_2026_09_04.md).

## 4. ⛔ The "We accept" logos are NOT ABA assets — this is a stop

The two PNGs prepared for the footer are **image generations**, not ABA artwork.
See [`REJECTED_AI_GENERATED/README.md`](./REJECTED_AI_GENERATED/README.md) for the
evidence: file times matching two ChatGPT exports to the minute, no authorship
metadata, an invented ABA-KHQR lockup, a detached red slash on the wordmark, and
a diffusion smear below the tile edge. ABA's real mark is visible in the footer
of ABA's own checkout page and looks nothing like them.

A "We accept" strip is an **acceptance mark**: a claim of a commercial
relationship made in a bank's registered trademark. Submitting a fabricated
version of ABA's mark to ABA, inside the merchant review ABA is conducting, is a
false attestation regardless of intent. The files are quarantined and are not
deployed.

**What ships instead:** `pwa_aba_marks.dart` names the method in type — `ABA
KHQR` in Ayden's own ink, in a hairline chip. True, verifiable, and no bank's
artwork is reproduced. Two constants, `kPwaAbaAcceptStripAsset` and
`kPwaAbaMethodMarkAsset`, are `null`; drop ABA's official file in `web/aba/` and
point a constant at it, and both widgets switch to artwork with no other edit.

The payment **modal needs nothing from ABA** — it shows ABA's own page, carrying
ABA's own KHQR header and ABA's own footer logo.

**Ask ABA for:** the official "We accept ABA KHQR" strip, the official compact
KHQR mark, and written permission to display both.

## 8. Known, and deliberately not worked around

* **ABA's page is cramped at 340 px.** It is a two-column layout that stops
  reflowing below roughly 500 px, so it scrolls internally inside the frame. An
  `OverflowBox` was tried to win back the sheet's 48 px of gutter and had to be
  reverted: in a Column with unbounded height it swallowed the sheet, covering
  the header, the escape link and the cancel button. A tighter QR is a smaller
  cost than a payment sheet with no way out.
* **The 180-second link vs the 30-minute transaction.** Already modelled
  (`needsFreshCheckout`, rendered as "start again", never as a failure). The deck
  shows no countdown; the sheet shows the transaction's own timer.
* **A blank frame is undetectable.** Cross-origin. That is exactly why the
  new-tab escape is permanent.
